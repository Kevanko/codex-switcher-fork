# Codex Switcher — проблема разлогина Claude и её решение

> Ветка: `safe-parked-accounts`
> Цель правок: заставить switcher вести себя с Claude-аккаунтами **как «выключенный ПК»** —
> припаркованный аккаунт полностью заморожен, его refresh-токен никто не трогает,
> сервер Anthropic доволен, а переключение между аккаунтами остаётся лёгким.

---

## 1. Симптом

- На Windows (где стоял switcher) Claude **выкинуло сразу со всех сессий** примерно через
  ~8 часов после апгрейда подписки MAX5 → MAX20.
- На ноутбуке (switcher не установлен, просто залогинен через `/login`) — **ничего не произошло**,
  токен прожил несколько дней.

«Выкинуло со всех сессий» — это не обычное протухание access-токена, а **глобальный отзыв
(revocation)** на стороне сервера.

## 2. Как устроена авторизация Claude (важно для понимания)

- `~/.claude/.credentials.json` хранит `accessToken` (короткоживущий, ~8 ч) + `refreshToken`.
- Access-токен по истечении обновляется через refresh-токен.
- **Anthropic применяет ротацию refresh-токена с детектором повторного использования**
  (refresh-token rotation + reuse detection): при каждом обновлении выдаётся **новый**
  refresh-токен, а **старый немедленно аннулируется**. Если кто-то предъявляет уже
  использованный (ротированный) refresh-токен — сервер считает это кражей токена и
  **аннулирует всё семейство токенов целиком → разлогин со всех сессий**.

Отсюда железное правило:

> **Одна цепочка refresh-токенов = один владелец, движение только вперёд, каждый токен
> используется ровно один раз.**

## 3. Корневая причина (root cause)

Switcher **в фоне ротировал refresh-токены неактивных (припаркованных) Claude-аккаунтов**,
чтобы рисовать полоску использования (usage bar):

| # | Где | Что происходило |
|---|-----|-----------------|
| 1 | `src/hooks/useAccounts.ts` (тик 60 c, неактивные ~6 мин) | фронтенд периодически дёргает обновление usage **для всех аккаунтов, включая неактивные Claude** |
| 2 | `api/usage.rs::get_usage_with_claude_auth` → `ensure_claude_tokens_fresh` | для **неактивного** аккаунта с истёкшим access-токеном вызывался `refresh_claude_tokens` |
| 3 | `auth/token_refresh.rs::refresh_claude_tokens` | POST на token endpoint → **сервер ротирует R1 → R2** |
| 4 | `api/usage.rs::get_usage_with_claude_auth` (ветка 401) | ещё одна прямая ротация неактивного аккаунта при 401 |

Пока окно switcher просто открыто, он каждые ~6 минут прокручивал токены припаркованных
аккаунтов. Как только одна из этих ротаций **раздвоила цепочку**, которую держит кто-то ещё
(ноутбук с тем же аккаунтом, либо устаревшая копия токена после апгрейда MAX5→MAX20),
другой держатель предъявил уже использованный токен → **reuse detection → revoke ALL**.

**Почему ноутбук выжил:** switcher там не стоял, usage никто не опрашивал, цепочка шла
строго вперёд и каждый токен использовался один раз. Это и есть поведение «выключенного ПК».

> Замечание: автор форка уже частично защитился (лок `CLAUDE_REFRESH_LOCK`, правило
> «не обновлять активный аккаунт», реконсиляция ротации, атомарная запись через temp-файл,
> авто-warmup исключает Claude). **Дыра оставалась ровно одна — usage-поллинг неактивных
> Claude-аккаунтов.**

## 4. Принятое решение — модель «выключенного ПК»

**Switcher больше НИКОГДА не обращается к token endpoint Claude.** Единственным «ротатором»
токена становится сам Claude Code (всегда только вперёд). Switcher лишь подменяет, какой
файл `.credentials.json` сейчас активен — буквально как «включил/выключил ПК».

Реализованные правки (ветка `safe-parked-accounts`):

1. **`auth/token_refresh.rs`**
   - `ensure_claude_tokens_fresh`: для **неактивного** аккаунта теперь возвращает его
     **как есть** (заморожен), вместо вызова `refresh_claude_tokens`. Для активного —
     как и раньше, только пере-чтение (sync) живого файла, без ротации.
   - **Полностью удалён `refresh_claude_tokens`** и вся сопутствующая машинерия
     (`ClaudeRefreshResponse`, `CLAUDE_REFRESH_LOCK`, константы token endpoint). Теперь в
     коде switcher **физически нет пути**, который мог бы ротировать Claude-токен.

2. **`api/usage.rs`**
   - `get_usage_with_claude_auth`: в самом начале определяет активность аккаунта. Для
     **неактивного** — сразу отдаёт `parked_claude_usage(account)` (последний кэш), **без
     единого сетевого запроса**. Для активного — живой запрос (его токен держит свежим
     Claude Code).
   - Новый помощник `parked_claude_usage`: отдаёт последний закэшированный `cached_usage`
     (вместе с таймерами сброса окон), либо нейтральный пустой бар, если кэша ещё не было.
   - Ветка 401 для активного аккаунта больше **не ротирует** — только пере-читает живой файл.
   - Убран импорт `refresh_claude_tokens`.

3. **`types.rs`**
   - Добавлен конструктор `UsageInfo::empty()` — нейтральный пустой снимок (без данных и без
     ошибки) для аккаунтов, у которых ещё нет кэша.

**Визуальный usage-бар не меняли** — для припаркованных аккаунтов он просто показывает
последнее известное значение и через сколько окно сбросится (данные берутся из `cached_usage`,
который уже содержит абсолютные таймстемпы сброса).

## 5. Что это даёт

- Припаркованный Claude-аккаунт **полностью заморожен**: switcher к нему не ходит вообще.
- Переключение = «включил ПК»: записывается сохранённый `.credentials.json`, и Claude Code
  сам делает **один** форвард-рефреш при первом использовании. Сохранённый refresh-токен
  валиден, потому что его никто после сохранения не использовал.
- Сервер Anthropic доволен: ни одного повторного предъявления токена со стороны switcher.

## 6. Остаточные риски / что ещё стоит разобрать

- [ ] **Один аккаунт — одна активная машина.** Switcher в одиночку не может предотвратить
      раздвоение цепочки, если один и тот же аккаунт **одновременно** активно используется на
      двух машинах (обе двигают цепочку вперёд независимо). Это нужно либо задокументировать
      как правило, либо добавить предупреждение в UI.
- [ ] **Захват свежего токока при switch-away.** Перед уходом с аккаунта switcher уже делает
      `sync_claude_tokens_from_file` для уходящего — убедиться, что это всегда успевает
      записать самый свежий refresh-токен в БД (иначе при возврате запишется устаревший).
      Проверить гонку, если Claude Code обновил токен ровно в момент переключения.
- [ ] **Реконсиляция внешней ротации.** `reconcile_active_claude_account` усыновляет
      внешне ротированный токен при совпадении org-UUID — оставить и покрыть тестом.
- [ ] **`update_account_claude_tokens`** в `storage.rs` теперь не используется (оставлен как
      `pub` для будущего flow «ре-логин по требованию»). Решить: удалить или задействовать
      для контролируемого one-shot рефреша при switch-in.
- [ ] **Опционально, defense-in-depth:** в `useAccounts.ts` вообще не дёргать сетевой usage
      для неактивных Claude (сейчас backend и так отдаёт кэш, но можно не делать лишний вызов).
- [ ] **Стаб `dist/`** в этой папке создан только чтобы скомпилировать Rust (`cargo build`).
      Для реальной сборки приложения нужен фронтенд: `pnpm install && pnpm build`.

## 7. Затронутые файлы

```
src-tauri/src/api/usage.rs            — parked_claude_usage, активный/неактивный путь, без ротации
src-tauri/src/types.rs                — UsageInfo::empty()
```
